# Контекст проекта

Мобильный веб-дашборд с инструкциями для водителей грузовиков. Водитель открывает одну ссылку, находит тему и читает PDF / документ / видео **прямо в приложении**. Файлы живут на Google Диске — здесь только витрина.

Боевой адрес: https://siahead2017-png.github.io/Driver_Instructions/

**Язык общения с пользователем — русский.** Интерфейс тоже только русский.

## Главное правило

**Никакой сборки и никаких зависимостей.** Чистые HTML/CSS/JS (ES-модули). Это не случайность, а осознанное решение:

- GitHub Pages отдаёт файлы как есть, без CI;
- владелец правит контент через веб-редактор GitHub, не открывая терминал;
- проект не протухнет через год без обновлений npm.

**Не предлагать** React, Vite, Tailwind, бандлеры, npm-пакеты. Если кажется, что без библиотеки не обойтись — почти наверняка обойтись можно.

## Окружение (важно)

На машине владельца **нет Node.js и нет рабочего Python** (`python` — заглушка Windows Store). Поэтому:

- локальный сервер — `serve.ps1` на PowerShell `HttpListener`, а не `npx serve` / `python -m http.server`;
- растровую графику генерировать через GDI+ (`Add-Type -AssemblyName System.Drawing`), а не Pillow.

Сервер обязателен: страница читает JSON через `fetch()`, из `file://` это запрещено.

**Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI** — кириллица в скриптах ломает парсер. Файлы `.ps1` в проекте держим **ASCII-only**. На этом уже один раз падал `serve.ps1`.

## Структура

| Файл | Назначение |
|---|---|
| `data/instructions.json` | **Всё содержимое.** Единственный файл для наполнения |
| `index.html` | Каркас: шапка, поиск, контейнер, модалка просмотра |
| `assets/js/app.js` | Загрузка данных, hash-роутинг, рендер экранов, поиск |
| `assets/js/drive.js` | Ссылка Диска → URL для встроенного просмотра, метаданные типов |
| `assets/js/store.js` | «Недавние» через localStorage |
| `assets/css/styles.css` | Мобильный дизайн, тёмная тема, цвета по типам файлов |
| `serve.ps1` | Локальный сервер для просмотра |

Экраны: плитки категорий → список с группировкой по подтемам → полноэкранная модалка. Навигация через hash (`#/category/tolls`, `#/item/tacho-regime`) — работает кнопка «Назад» на телефоне и можно дать ссылку сразу на инструкцию.

## Модель данных

Плоский список `items` + отдельный `categories`. Плоский намеренно: проще искать и дописывать.

- `category` ссылается на `categories[].id`;
- `subtopic` — необязательная группа внутри категории, появляется автоматически;
- `categories[].subtopics` — необязательный список, задаёт **порядок** групп. Карточки без `subtopic` всегда сверху; подтема не из списка встаёт в конец; подтема без карточек не показывается;
- `type`: `pdf` | `doc` | `sheet` | `slide` | `image` | `video` | `link`.

Полный справочник полей и инструкция для владельца — в [README.md](README.md).

## Просмотр файлов

`drive.js` вытаскивает file ID регуляркой из любой формы ссылки Диска и строит embed-URL:

- обычный файл (pdf, video, jpg) → `drive.google.com/file/d/{ID}/preview`
- Google Docs → `docs.google.com/document/d/{ID}/preview`
- Sheets / Slides → аналогично

Проверено на живых файлах: PDF, mp4, JPG и загруженный `.pptx` открываются встроенно нормально.

**Обязательное условие:** у файла на Диске должен быть доступ «Все, у кого есть ссылка — Читатель». Иначе iframe покажет пустой экран. При добавлении новых ссылок это стоит проверять — самая частая причина «не работает».

Если ID не распознан или встроить нельзя, показывается запасной экран с кнопкой «Открыть на Google Диске». Есть таймаут 8 секунд на случай закрытого доступа.

## Как проверять изменения

`.\serve.ps1` → http://localhost:8000, дальше через браузер.

Полезные проверки, которые уже ловили баги:
- валидность JSON, дубли `id` и `url`, сироты `category`, расхождения `subtopic` со списком;
- русские склонения счётчиков (`plural()` в `app.js`) — на этом был баг «4 инструкций»;
- модалка: iframe выгружается при закрытии, иначе видео играет фоном;
- отсутствие горизонтального скролла на 375px.

Браузер агрессивно кеширует `instructions.json` — при проверке добавляй `?v=что-нибудь` к URL, иначе увидишь старые данные и решишь, что сломал рендер. После пуша GitHub Pages собирается ~1 минуту.

## Открытые хвосты

1. **Видео TELEPASS (4 шт.)** названы «часть 1–4» условно, по порядку ID. Настоящих названий нет — на Диске это `VID-20251114-WA0001…0004.mp4`. Владелец обещал посмотреть и сказать, что в каком ролике.
2. **Описаний нет у большинства карточек.** Содержимое файлов не читалось — выдумывать описания нельзя. Если понадобятся, сначала прочитать файлы, потом писать по факту.
3. **Дубли на Диске:** «ПАМЯТКА ПО ОПЛАТЕ ДОРОГ» и «SMSVinjette» лежат в двух экземплярах с разными ID. В дашборде по одной копии.
4. **Спорная раскладка:** «Топливные карты» → Топливо, «Фоторадары» → Безопасность (владелец присылал их в группе «оплата дорог»). Категории «Погрузка и разгрузка» и «Безопасность» предложены мной, не им.
5. Если «страновых» файлов (мойки в Польше, туннель в Нидерландах) станет больше — завести категорию «Маршруты и страны».

## Публикация

GitHub Pages, ветка `main`, папка `/`. Пуш = деплой.

Коммиты в этом репозитории подписываются рабочей личностью через `--local` конфиг; глобальная настройка на машине владельца — личная, её не трогать. В remote URL зашит username, чтобы Credential Manager не подставлял личный аккаунт.

## Тон

Владелец — не программист. Объяснять простым языком, без жаргона. Давать готовые команды целиком, а не «настрой X». Он ценит, когда честно называешь, что проверено, а что нет.
