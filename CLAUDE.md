# Контекст проекта

Мобильный веб-дашборд с инструкциями для водителей грузовиков компании HEAD, HDLG. Водитель открывает одну ссылку, находит тему и читает PDF / документ / видео прямо в приложении. Файлы живут на Google Диске — здесь только витрина.

Боевой адрес: https://siahead2017-png.github.io/Driver_Instructions/

**Язык общения и интерфейса — русский.** Владелец — не программист: объяснять просто, давать готовые команды целиком, честно разделять «проверено» и «не проверено».

## Главное правило

**Никакой сборки и никаких зависимостей.** Чистые HTML/CSS/JS (ES-модули): GitHub Pages отдаёт как есть, владелец правит контент через веб-редактор GitHub, проект не протухает. **Не предлагать** React, Vite, Tailwind, npm-пакеты.

## Окружение

Сборки, тестов и линтера в проекте нет — только эти команды:

```powershell
.\serve.ps1                                                                     # локальный сервер -> http://localhost:8000
node --check assets/js/app.js                                                   # синтаксис-чек после правки любого .js
node -e "JSON.parse(require('fs').readFileSync('data/instructions.json','utf8'))"  # валидность JSON после правки контента
node -e "JSON.parse(require('fs').readFileSync('data/guide.json','utf8'))"         # то же для гида
```

- **Нет рабочего Python** (`python` — заглушка Windows Store). Node.js есть (v24) — годится для `node --check` и смоук-тестов, но npm-зависимостей в проект не тянуть.
- Локальный сервер — `serve.ps1` (PowerShell `HttpListener`, порт задаётся `-Port`); обязателен, т.к. `fetch()` не работает из `file://`. Отдаёт файлы с `Cache-Control: no-store`, так что кеш `?v=` — забота только продакшена (GitHub Pages / телефон), не локального сервера.
- **`.ps1` держать ASCII-only**: PowerShell 5.1 читает файлы без BOM как ANSI, кириллица ломает парсер (уже падал `serve.ps1`).
- Растровую графику генерировать через GDI+ (`System.Drawing`), не Pillow.

## Модель данных

Плоские `items` + `categories` (намеренно — проще искать и дописывать). `category` → `categories[].id`; `subtopic` — необязательная группа, появляется сама; `categories[].subtopics` задаёт порядок групп; `type`: `pdf|doc|sheet|slide|image|video|link`. `important: true` — критично важное: рендерится в отдельной секции «❗ Важно» первым блоком на главной (до «Недавних» и категорий, `renderHome()` в `app.js`) и подсвечивается красным (`.card--important`, токен `--danger` в `styles.css`) везде, где карточка встречается — в категории и в поиске тоже. Не «прочитывается» и не пропадает сама — висит, пока флаг не уберут из JSON. Справочник полей — в [README.md](README.md).

## Просмотр файлов

## Виджет-калькулятор (`calc.js`)

Плавающая кнопка `.calc-fab` (оранжевая пилюля, вся графика чистым CSS) → модалка `.calc` (`z-index: 60`) с **двумя вкладками**: «Время и топливо» и «Остатки топлива в баке». «Сбросить» сбрасывает обе вкладки.

**Время:** `driveMin = dist/speed*60`; паузы = `9 × p9Count` + чекбоксы 24/45/2 ч + своя пауза. «Пауза 9 ч» — **степпер** (девяток в рейсе 2–3): − / надпись `×N` / +, тап по надписи +1, максимум `P9_MAX = 5`, подсветка классом `.is-on`. `fmtHHMM()` без ограничения 24 ч. Обязательные перерывы по регламенту ЕС осознанно НЕ считаем — только отмеченное водителем.

**Топливо** (галочка, по умолчанию вкл): «Тягач (по км)» = `дист/100 × расход` (дефолт 27); «Двигатель на стоянке» = `часы × IDLE_LPH` — константа **2,5 л/ч зашита, водителю не показывается**, строка видна при часах > 0, на время в пути не влияет; **«Итого тягач»** = км + стоянка; **«Итого прицеп»** = `totalMin/60 × расход` (дефолт 1,8 л/ч, рефустановка). Общего «Всего» нет — владелец убрал (заправляются раздельно). `fmtL()` — ru-RU, до 2 знаков (1 знак округлял 8,77 → «8,8», водителей смущало).

**Остатки в баках:** марка радио-чипами MAN/DAF/VOLVO (дефолт MAN), у каждой два бака; литры = `см × lPerCm`. Данные — объект `TANKS` (`cap` для подписи «Бак N (580 л), см», `lPerCm`, памятка `note` про отметку линейки и полный бак):

| Марка | Бак 1 | Бак 2 | Полный / линейка |
|---|---|---|---|
| MAN | 580 л, 8,65 л/см | 580 л, 8,65 | 67 см / 70 см |
| DAF | 845 л, **14,08** | 355 л, 5,58 | 60 см / 64 см |
| VOLVO | 570 л, 8,77 | 650 л, 10,00 | 65 см / 71 см |

Коэффициент DAF-1 **выведен** (845/60): присланные владельцем 8,65 не сходились с подтверждённой ёмкостью 845 л. Сантиметры хранятся по каждой марке отдельно (`tankCm`) — переключение марки не теряет замеры.

**Состояние:** ключ localStorage `di:calc`, TTL 5 мин, всё в `try/catch` (приватный режим). Дефолты в `setDefaults()`.

**Тонкости:** снятие `is-opening` через `setTimeout`, не rAF (rAF молчит в фоновой вкладке); против горизонтального скролла — `min-width: 0` на карточке/панелях/полях; чипы подсвечиваются `:has(input:checked)`, степпер — классом.

## Гид по инструктажу (`guide.js`)

Пошаговый разбор базы знаний для новых водителей — вход крупным баннером `.guide-banner` на главной (выше блока «❗ Важно»), сам гид — полноэкранный оверлей `.guide`. Второй прецедент «фичи поверх модели категорий» после калькулятора, но с важным отличием: гиду обязательно нужно передавать управление на настоящую карточку (`viewer`) и возвращаться назад на тот же шаг — калькулятор с этим никогда не сталкивался. Поэтому гид, в отличие от `calc.js`, участвует в hash-роутинге как собственный «виртуальный экран».

**Hash-схема:** `#/guide` (последний открытый шаг из прогресса, либо первый) и `#/guide/<stepId>`. Подтверждено чтением `app.js:72-99`: `route()`/`render()` проверяют только `'category'` и `'item'`, всё остальное (в т.ч. `'guide'`) безопасно уходит в `else renderHome()` — контракт не задокументирован в `app.js` явно, если там появится новый `else if` для экрана, перепроверить, что `'guide'` по-прежнему не перехватывается.

**Разделение push/replace — самое важное здесь:**
- Открыть гид с баннера / открыть карточку из шага → `location.hash = '#/guide/...'` или `<a href="#/item/...">` — обычная навигация, пишет запись в history.
- «Далее»/«Назад»/тап по чипу блока внутри гида → `history.replaceState(...)` + локальный ререндер в `renderStep()` — **не** пишет запись. Без этого после N пролистываний кнопка «Назад» на телефоне не смогла бы выйти из гида за один тап (`replaceState` вдобавок не порождает `hashchange` — `app.js` не перерисовывается на каждом шаге).
- Закрыть гид — `history.back()`, плюс запасная кнопка «на главную» (`location.hash = ''`) — на случай прямой ссылки на шаг без предыдущей записи в history (`history.back()` в этом случае уводит за пределы сайта, проверено).

**Показ/скрытие** — через `hidden`, не только z-index (`.guide` = 45, между `calc-fab` 40 и `viewer` 50): иначе элемент остаётся в tab-order и ловит фокус с клавиатуры позади открытой карточки. **Отдельно найденный баг**: `.calc-fab { display: flex }` специфичнее браузерного `[hidden] { display: none }` — просто выставить `fab.hidden = true` из `guide.js` было недостаточно, фокус всё равно проваливался в невидимую кнопку. Понадобился явный `.calc-fab[hidden] { display: none }` в `styles.css`. `guide.js` прячет/показывает `calc-fab` вместе с собой.

**`is-locked` конфликт**: `viewer`, `calc` и `guide` используют один общий класс блокировки скролла. `hideGuide()` снимает `is-locked` только если `viewer.hidden === true` в этот момент — иначе гид собьёт блокировку, которую только что поставил открывшийся `viewer` (чтение публичного DOM-состояния, не импорт из `app.js`).

**Данные**: `data/guide.json` — отдельный файл, а не ключ в `instructions.json`, сознательно: у `instructions.json` один общий `fetch`+`JSON.parse` на весь каталог, опечатка в гиде не должна ронять главную/категории/поиск. Схема: `{ blocks: [{ id, title, icon, steps: [{ id, title, text: [...абзацы], items: [...item.id], confirm }] }] }`. `items` — существующие `item.id` из `instructions.json`, резолвятся через `typeMeta` из `drive.js` (та же импортированная утилита, что и в `app.js`); несуществующий id не падает, а рендерится как «Материал недоступен» (`.guide-link--broken`). `confirm` — если есть, на шаге появляется чекбокс, отметка пишет прогресс.

**Прогресс**: `localStorage`, ключ `di:guide`, **без TTL** (в отличие от сессионного `di:calc` — водитель возвращается через дни/недели). `{ current, done: {stepId: true} }`. «Сбросить прогресс» — `confirm()` + `localStorage.removeItem`.

**Галочка обязательна для перехода дальше (правка 02.08.2026).** Раньше `goDelta()` сам вызывал `markDone()` при нажатии «Далее» — из-за этого шаг считался пройденным по факту пролистывания, и при возврате назад галочка оказывалась уже отмеченной, хотя водитель её не трогал (владелец заметил это на живом прогоне). Теперь отметку ставит **только** сам чекбокс: `markDone()` на установку, `unmarkDone()` на снятие (снятие обязано стирать отметку — иначе её можно было бы поставить, вернуться и снять, а шаг остался бы зачтённым). Кнопка «Далее»/«Готово ✓» блокируется через `syncNextBtn(step)`, пока `done[step.id]` не выставлен; проверка продублирована в самом `goDelta()`, т.к. вперёд ведёт не только кнопка. У шага без `confirm` блокировки нет. Визуально: `.guide__nav .btn:disabled { opacity: .4 }` (уже было) плюс `.guide-check:has(input:not(:checked))` красит рамку галочки в акцент — иначе водитель не понимает, почему кнопка неактивна.

**Лента блоков едет за шагом**: `renderChips()` вызывает `scrollActiveChipIntoView()` — активный чип подвозится к центру `#guide-chips` через `chipsEl.scrollTo({left})`. Важно скроллить **саму ленту**, а не `scrollIntoView()` на чипе: последний утягивает и вертикальный скролл страницы. `behavior` уважает `prefers-reduced-motion`. До этой правки лента стояла на месте, и на шагах из середины гида подсвеченный блок оставался за правым краем — казалось, что заголовок не совпадает с вопросом.

Последний шаг («Готово ✓» на самом последнем шаге, а не просто «Далее») больше не закрывает гид: `goDelta()` переводит на `#/register` — см. ниже.

Контент адаптирован из отдельного инструмента `Driver_Briefing` (там формулировки уже согласованы в нескольких раундах правок с владельцем, ссылки на `item.id` подобраны) — со снятием служебных пометок для ведущего и с добавлением блоков, которых в `Driver_Briefing` нет (отчёты отдела учёта, фотофиксация транспортного контроля — весь инструктаж, а не только часть владельца).

## Регистрация после инструктажа (`register.js`)

Этап 2 плана «Электронный инструктаж водителя с подписью» (этап 1 — гид выше). Свой виртуальный экран `#/register`, тот же приём, что у гида: `app.js` его не знает, `route()`/`render()` безопасно уходят в `renderHome()`. Открывается автоматически с последнего шага гида (`guide.js`: `goDelta()`, `delta > 0 && !next` → `location.hash = '#/register'`), закрывается через `history.back()` — возвращает на тот же шаг гида, с которого пришли.

**Координация `is-locked` / `calc-fab` с гидом** — тот же паттерн, что у `guide.js` с `viewer`, но зеркальный: `hideRegister()` перед снятием `is-locked` и показом `calc-fab` проверяет `hidden` и у `#guide`, и у `#viewer` — не трогает их, если один из этих экранов уже открылся. Работает благодаря порядку `<script>`-тегов в `index.html` (`guide.js` раньше `register.js`): на переход `guide → register` первым отрабатывает `hideGuide()` (снимает лock), затем `showRegister()` (ставит обратно) — в одном тике `hashchange`, без перерисовки между вызовами. На `register → guide` — наоборот, `showGuide()` первым, `hideRegister()` вторым видит `guide` уже открытым и не трогает общее состояние.

**Поля:** компания трудоустройства (радио-карточки с логотипом, `COMPANIES` в начале `register.js` — `HEAD`/`HDLG`, первая в списке выбрана по умолчанию; логотипы `assets/img/logo-head.png`/`logo-hdlg.png`, тот же приём скрытого radio + `:has(input:checked)`, что у `.calc__chip` в `calc.js`), Фамилия и Имя отдельными полями (отчество сознательно не собираем — не нужно), дата рождения (`<input type="date">`, конвертация в `dd.mm.yyyy` через `fmtDateRu()` — тот же принцип границы ISO/отображение, что в `WEB-SIGNATURE/server/format.js`), e-mail — **необязательное** поле (см. ниже), подпись — `SignaturePad` из `signature-pad.js` (canvas создаётся заново в `renderForm()` при каждой пересборке формы, задача завязана на реальный размер контейнера: `el.hidden = false` обязан произойти ДО создания `SignaturePad`, иначе `getBoundingClientRect()` даст 0×0). Линейка/подсказка «Распишитесь здесь» — чистый CSS (`.register__pad::before/::after`), на канвасе рисуется только сама подпись — то же правило, что в `WEB-SIGNATURE`.

**E-mail необязателен**: `validate()` не требует непустого значения, проверяет формат только если что-то введено. Если поле пустое, `handleSubmit()` перед отправкой спрашивает через `confirm()` — не у всех водителей есть рабочая почта, отправка всё равно уходит в Sheet/PDF, просто письмо с подтверждением никуда не придёт (`sendEmail_` в `Code.gs` тоже просто пропускает отправку, если и `email`, и `CONFIG.NOTIFY_EMAIL` пусты).

**Предпросмотр текста согласия (`.register__confirm`)**: перед подписью водитель видит блок с тем же текстом, что уйдёт в тело PDF (без шапки с логотипом/реквизитами) — по просьбе владельца 01.08.2026, чтобы не было вопросов «что я вообще подписываю». Текст держится в `CONFIRM_TOPICS`/`confirmationHtml()` в `register.js`, **дублирует** тело `PDF_TEMPLATES.txt` вручную — при правке формулировок надо поправить оба места. Бейдж «Черновик текста — формулировки ещё не проверены юристом» убран (02.08.2026) — текст согласован, больше не помечается как черновик. Реагирует на выбор компании: слушатель `change` на `input[name="reg-company"]` подменяет `#register-confirm` через `outerHTML` (не весь `renderForm()` — иначе слетел бы canvas подписи). Блок — `max-height: 220px; overflow-y: auto` внутри `.register__body` (который сам `display:flex; flex-direction:column`) — обязателен `flex-shrink: 0` на `.register__confirm`, иначе длинный блок сжимается почти до нуля вместо собственного скролла (флексбокс отдаёт освобождающееся пространство самому большому по контенту элементу, если у него нет `flex-shrink:0` и `overflow` не `visible` — нашли на практике 01.08.2026, другие короткие поля формы эту особенность никогда не проявляли).

**Backend подключён.** «Отправить» валидирует поля локально (`validate()`), сразу пишет итоговый payload (`company`, `lastName`, `firstName`, `birthDate`, `email` — может быть `''`, `signature` — PNG dataURL, обрезанный по чернилам, `submittedAt`) в `localStorage` (`di:register:last`) на случай обрыва сети, и отправляет его в Apps Script Web App через `fetch(ENDPOINT_URL, { headers: { 'Content-Type': 'text/plain' } })` (без preflight, см. CORS-заметку ниже). Три экрана-состояния: «Отправляем…» (`renderSending`, спиннер), «Не получилось отправить» (`renderSubmitError` — данные не теряются, кнопка «Повторить» переиспользует уже собранный `payload` напрямую, не перечитывая форму и не спрашивая e-mail-confirm повторно) и «Данные собраны» (`renderDone` — только после `{ ok: true }` от сервера; `localStorage` очищается только тут; текст и колонка E-mail меняются в зависимости от того, был ли он указан). `ENDPOINT_URL` — константа в начале `register.js`, уже вписан реальный боевой URL Web App (см. «Публикация: что нельзя пушить» ниже — это единственный секрет-подобный параметр, который осознанно остаётся публичным).

Серверная часть — `Driver_Instructions_Backend/` (вне этого репозитория, `Code.gs`): принимает payload, пишет строку в Google Sheet (`CONFIG.SPREADSHEET_ID`). **Колонки по порядку (обновлено 01.08.2026)**: № (`sheet.getLastRow()` до `appendRow()` — с учётом строки заголовка это и есть порядковый номер новой строки), фамилия, имя, дата рождения, e-mail, дата и время инструктажа с сайта (`submittedAt`), компания, **ссылка на PDF** (последней колонкой, `RichTextValue.setLinkUrl()` на `pdfFile.getUrl()`, не формула `HYPERLINK()` — у неё разделитель аргументов зависит от локали таблицы, `RichTextValue` от локали не зависит). Старый отдельный столбец «дата отправки» (серверное время, `new Date()` в момент `doPost`) убран — почти всегда совпадал с `submittedAt` и дублировал его; единственная дата в строке теперь `submittedAt`. Из-за этого в `doPost` порядок вызовов сменился: **`buildPdf_` теперь выполняется до `appendToSheet_`** (раньше — наоборот), чтобы в Sheet передать готовый `pdfFile` для ссылки; побочный эффект — строка в Sheet больше не может появиться без готового PDF (раньше при падении `buildPdf_` после успешного `appendToSheet_` в Таблице оставалась «осиротевшая» строка без PDF и письма). **Владельцу нужно вручную**: удалить старый столбец B «Дата отправки» в самой Таблице (Sheets сам сдвинет всё влево — бывший G «Время отправки» станет F, бывший H «Компания» станет G), переименовать шапку бывшего G в «Дата и время инструктажа», добавить шапку в новом H — «Ссылка на PDF»; затем передеплоить `Code.gs`. Все даты в Sheet пишутся текстом через `Utilities.formatDate(..., 'dd.MM.yyyy HH:mm')`, не сырым `Date`/ISO-строкой — иначе вид ячейки зависит от локали таблицы (это и была причина «некрасивых» дат/ISO-меток при первой проверке). Собирает PDF из шаблона Google Docs — **шаблон выбирается по компании**, `CONFIG.TEMPLATES.HEAD` / `CONFIG.TEMPLATES.HDLG`, у каждого своя шапка (лого + реквизиты), но одинаковый текст ниже (тексты обоих — `PDF_TEMPLATES.txt` рядом с кодом). Плейсхолдеры `{{ФИО}}` (склеивается из `lastName`+`firstName`), `{{ДАТА_РОЖДЕНИЯ}}`, `{{EMAIL}}` (если пусто — код сам подставляет «не указан»), `{{ДАТА_ИНСТРУКТАЖА}}`, `{{ПОДПИСЬ}}` заменяются через `Body.replaceText()` — фигурные скобки экранируются как `\{\{...\}\}`, т.к. это RE2-регулярка; подпись вставляется как inline-картинка на место удалённого текста-плейсхолдера, который должен занимать целый абзац. Имя файла PDF (и промежуточного Doc) — `${Фамилия} ${Имя} ${дата рождения} — Инструктаж.pdf` (по просьбе владельца 01.08.2026, начинается с ФИО+даты, не с «Инструктаж»). **Гоча №1 (нашли и исправили 01.08.2026): шаблон обязан быть НАСТОЯЩИМ Google Doc, не загруженным Word/PDF-файлом.** Владелец изначально загрузил/скопировал на Диск файл Word/PDF вместо создания нового «Google Документа» — `DriveApp.getFileById(...).makeCopy()` такой файл спокойно копирует (это просто файл), но `DocumentApp.openById()` на результат падает с общей ошибкой `Документ недоступен. Повторите попытку позже.` — сообщение не намекает на реальную причину (формат файла), выглядит как временный сбой. Проверяли повторными попытками с паузой (`openDocWithRetry_`, 5×1с) — не помогло, ошибка стабильная, что и стало ключевой уликой (не тайминг, а фундаментальная невозможность открыть). Решение: создать **новый пустой Google Doc** (Диск → + Создать → **Google Документы**, не «Загрузить файл») и вставить текст/лого туда — после этого всё сразу заработало. `PDF_TEMPLATES.txt` теперь явно предупреждает об этом.

**Гоча №2: тестировать API этого Web App нужно через настоящий браузер (`fetch()`), не `curl`.** `curl -X POST` регулярно возвращал то `411 Length Required` (нужен явный `Content-Length`, `--data-binary @file` иногда не проставляет его через этот прокси), то `502` или зависание на редиректе `script.google.com → script.googleusercontent.com`. При этом в панели «Количество выполнений» (Apps Script) сами вызовы `doPost` были видны и завершались нормально — значит, ломался именно `curl`/редирект на клиенте, а не сервер. Через `chrome-devtools` MCP (`fetch()` из реальной страницы) всё работало сразу. Этот же паттерн уже встречался раньше при проверке CORS (см. память проекта) — не наступать на те же грабли дважды.

**Гоча №3 (найдена и исправлена 01.08.2026): `escapeForReplace_` экранировала не тот аргумент.** В `Code.gs` подставляемые в PDF значения (ФИО, дата, e-mail) проходили через ту же экранировку регекс-спецсимволов, что и искомый паттерн (`ph_`) — но у `Body.replaceText(pattern, replacement)` регуляркой является только `pattern`; `replacement` — обычный текст, где спецсимвол только один: `$` (бэкреференс на группу). В результате в реальный PDF попадали лишние обратные слэши перед точками — «10\.07\.1990», «konstantins\.persins@gmail\.com» — владелец заметил визуально, открыв тестовый PDF. Исправлено: `escapeForReplace_` теперь заменяет только `$` → `$$`, остальные символы не трогает. **Фикс не переверялся живым тестом на боевом Apps Script** — только логически (юнит-проверка в Node) и то, что фронтенд-часть (`register.js`/CSS) не пострадала; следующий тестовый прогон должен явно свериться, что слэшей в PDF больше нет.

**Гоча №4 (02.08.2026): лишняя первая страница «Вкладка 1» в PDF — свойство самого Doc-шаблона, а не кода.** В присланном по почте PDF (шаблон HDLG) появился лишний первый лист с единственным текстом «Вкладка 1», документ уехал на страницу 2. «Вкладка 1» — имя единственной вкладки в панели «Вкладки в документе» (Tabs, новая функция Google Docs), оставленное по умолчанию. Две гипотезы оказались неверными: (1) мусор в теле документа — его там не было; (2) виноват конвертер `getAs('application/pdf')` — переход на `https://docs.google.com/document/d/<id>/export?format=pdf` (то, что дёргает меню «Файл → Скачать → PDF») лишнюю страницу **не убрал**, как и добавление `&tab=<id вкладки>`. Настоящая причина нашлась сравнением двух шаблонов через Google Drive MCP (`get_file_metadata` → `contentSnippet`): текст HDLG начинался с «Вкладка 1», текст HEAD — сразу с реквизитов, т.е. у HEAD вкладок нет и он всегда экспортировался чисто даже старым `getAs()`. **Лечение — пересоздать проблемный шаблон копией рабочего** (Файл → Создать копию с HEAD, заменить в копии шапку и название компании в GDPR-абзаце), а не чинить кодом. **Приём на будущее: странное поведение Google Doc при экспорте — сравнить `contentSnippet` с заведомо рабочим документом, разница видна сразу.** В коде от этой истории остался `exportDocAsPdf_()` через `UrlFetchApp` (честный эквивалент меню «Скачать», лучше `getAs()`), но без параметра `tab`. **Из-за `UrlFetchApp` добавился OAuth-scope `script.external_request` — скрипт надо переавторизовать вручную** (запустить любую функцию из редактора → «Разрешить»), иначе Web App упадёт; только после этого Deploy → New version. Служебная `проверитьЭкспортPDF()` кладёт в папку PDF два файла «ТЕСТ ЭКСПОРТА — HEAD/HDLG.pdf» для быстрой проверки экспорта без полного цикла регистрации; в ней же гоча — `folder.getFilesByName()` возвращает `FileIterator`, не массив, `.forEach` падает.

**Диагностика через `Logger.log`**: добавлены логи в `doPost` (catch) и `openDocWithRetry_` (каждая попытка) — владелец как не-программист с трудом ориентируется в панели «Количество выполнений» Apps Script (путает её с контекстным меню «⋮»), поэтому основной способ диагностики на будущее — читать текст ошибки прямо из ответа сервера (он всё равно приходит в `{ok:false, error}`, видно в консоли браузера), а не лезть в Executions.
